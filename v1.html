第 1 章 · 预训练 · 阶段 1

下载
整个互联网

第一步是收集海量的文本。Common Crawl 这类机构自 2007 年起就在持续抓取网页——单次月度抓取约含 27 亿网页（2024 年量级），自 2007 年以来的累计存档则远大于此。这些原始数据再被过滤为像 FineWeb 这样的高质量数据集。

目标是：大量、高质量且多样化的文档。经过激进的过滤后，最终大约剩下 44 TB——相当于 10 块消费级硬盘的文本——约对应 15 万亿 token。

科学批注FineWeb 的“44TB/15T”应标成特定版本量级；公开数据页后续已更新，不能作为永久规格。
核心洞察 训练数据的质量与多样性，对最终模型表现的影响几乎超过其他一切因素。垃圾进，垃圾出——只不过这里的"垃圾"是万亿 token 量级的。

第 1 章 · 预训练 · 阶段 2

分词（Tokenization）

神经网络无法直接处理原始文本——它需要数字。解决办法就是分词：把文本切分成 token（子词块），并为每个 token 分配一个 ID。

GPT-4 使用一个 100,277 个 token 的词表，通过字节对编码（BPE）算法构建。BPE 从单个字节（256 个符号）开始，反复合并出现频率最高的相邻字节对——在压缩序列长度的同时扩展词表。

科学批注100,277 是公开 `cl100k_base` 分词器量级，不是 GPT-4 官方披露的词表大小。GPT-4 tokenizer 细节未公开确认。
为什么不直接用单词？ 单词的变体是无穷的。"run"、"running"、"runner" 会变成 3 个独立条目。子词 token 共享词根："run" + "ning"、"run" + "ner"。这样还能高效处理新词、拼写错误以及多种语言。

第 1 章 · 预训练 · 阶段 3

训练
神经网络

Transformer 神经网络以随机参数初始化——数十亿个"旋钮"。训练就是调整这些旋钮，让网络更善于预测任意序列中的下一个 token。

每一步训练：采样一段 token 窗口 → 输入网络 → 比较预测与真实下一个 token → 把所有参数朝正确方向轻轻推一点。重复数十亿次。

loss——一个度量预测误差的单一数值——会随着模型不断学习人类语言的统计规律而稳步下降。

规模 GPT-2（2019 年）：16 亿参数，1000 亿 token，训练约 4 万美元。今天：同等质量大约只需 100 美元。Llama 3：4050 亿参数，15 万亿 token。现代前沿模型：数千亿参数、万亿级 token。 科学批注GPT-2 最大公开版本是 1.5B 参数，WebText 约 40GB；“1000 亿 token”和“同等质量 100 美元”都缺少背景，容易把玩具级复现误写成完整 GPT-2 复刻。

Transformer 架构

什么是 Embedding？ 每个 token ID 会映射到一个学习得到的、约 1,000–4,000 维的向量，称作它的 embedding。可以把它理解为意义空间中的一个坐标——初始随机，再由训练塑形。同一个 token（比如 "bank"）总是以同一个 embedding 向量进入网络。注意力层（attention）随后会把上下文 token 的信息混入其中，所以当 "bank" 流到更深层时，"river bank（河岸）"和 "bank account（银行账户）"会带有完全不同的表示。一词多义是靠上下文消解的，而不是给一个 token 存多个含义。

第 1 章 · 预训练 · 阶段 4

推理与
Token 采样

训练完成后，网络以自回归方式生成文本：输入一段 token → 得到所有 10 万个候选 token 的概率分布 → 采样一个 → 追加 → 重复。

这个过程是随机的——同样的 prompt 每次产生不同输出，因为我们在掷一枚有偏的硬币。概率高的 token 更有可能被选中，但并不保证。

Temperature 控制随机性。低 temperature（0.1）→ 模型总挑最高概率的 token；高 temperature（2.0）→ 接近均匀的混乱。0.7–1.0 是兼顾连贯与创造性的甜区。

关键心智模型 模型不会"思考"该说什么。它在所有可能的下一个 token 上算出一个概率分布，然后采样。每个词都是一次抛硬币——只是一次极其有信息量的抛硬币。

第 2 章 · 基础模型

互联网
模拟器

预训练完成后，你得到的是一个基础模型——一个高级的自动补全引擎。它不是助手，不会答问题。它只会基于在互联网上看到的内容把 token 序列接着写下去。

给它一句维基百科的话，它会凭记忆补全。问它"2+2 等于几？"，它可能给你一页数学课本、一份测试答案，或干脆扯到别处去——取决于训练数据里这种问句之后统计上最常出现的延续是什么。

基础模型的知识存放在它的 4050 亿个参数里——一份对互联网的有损压缩，类似一个"近似而非精确"地存储信息的 zip 文件。

第 3 章 · 后训练

把基础模型变成助手

基础模型只是一个 token 模拟器。要把它变成有用的助手，需要后训练——一个成本低得多但同样关键的阶段。这是模型学会对话的地方。

监督微调（SFT，Supervised Fine-Tuning）

人工标注员遵循详细的标注规范，构造一份"理想对话"数据集：要有用、要真实、要无害。然后在这些对话上继续训练模型——不是从零开始，而是在预训练得到的权重上用这份新数据继续微调。

现代 SFT 数据集（例如 UltraChat）有数百万条对话——大部分是合成的（LLM 生成的），再经人工审校。模型通过模仿来学习：它接管了数据中所体现的"理想助手"人设。

训练对话示例
Human
2 + 2 等于多少？
Assistant
2 + 2 = 4。还有什么我可以帮您的吗？
Human
如果换成乘法呢？
Assistant
2 × 2 也等于 4——结果一样！乘法上，2 × 2 表示 2 自加一次，结果是 4。
你究竟在跟谁对话 ChatGPT 是 OpenAI 雇佣的人类标注员的统计模拟——这些标注员是按照标注规范作答的专家。当它回答一个编程问题时，它在模仿一名熟练的开发者标注员会怎么写。

对话的 token 格式

每段对话都必须被编码成一维 token 序列。特殊 token 标记结构：

<|im_start|>user<|im_sep|> 2 + 2 等于多少？ <|im_end|> <|im_start|>assistant<|im_sep|> 2 + 2 = 4. <|im_end|>

第 4 章 · LLM 心理学

语言模型的
认知怪癖

要理解 LLM 行为背后的原因，得从它的"心理学"角度来看——这些都是"被训练去统计性模仿人类文本"所涌现出的属性。

🌀
幻觉（Hallucination）
模型会自信满满地胡编，因为训练数据里总是充满自信的回答。"Orson Kovats 是谁？" 会换来一份编出来的人物履历——因为训练数据里"X 是谁？"这种问题的统计分布后面跟的总是自信的回答，哪怕名字是虚构的。修复方式：对模型一贯答错的问题，加入"我不知道"的样本。
🧠
两种记忆
参数 = 长期记忆。模型在训练阶段学到的一切——浩瀚但模糊，就像几个月前读过的东西。上下文窗口 = 工作记忆。当前对话里的文本——精确、可直接访问。重要信息一定要贴进上下文，不要指望模型自己"记得"。
🔧
工具调用
模型可以输出特殊 token 来触发外部工具：<search>query</search>。运行程序会暂停生成、执行搜索、把结果塞回上下文窗口，再继续生成。模型"查资料"的方式跟你一样——刷新工作记忆。
🪞
没有持久的"自我"
每段对话都从头开始——没有之前对话的记忆。模型"开机"，处理 token，然后"关机"，没有稳定的身份。当它说"我是 OpenAI 的 ChatGPT"，那只是训练数据里统计上最可能的回答——而不是真正的自我认知。
📊
随机的 Token 转盘
模型不会"决定"说什么。它在算概率分布，然后采样。同一个 prompt 跑 10 次，会得到 10 个不同的输出——每一个都合理，都来自同一个学到的分布。Temperature 控制采样从这个分布中铺得多宽。
📚
知识截止（Knowledge Cutoff）
训练数据有一个截止日期。模型确实不知道这之后发生了什么。问它最近的事件，它会胡编——不是出于恶意，而是它回答任何问题时都用同一个机制：预测 token 序列最可能的延续。
LLM 应用 · RAG

检索增强
生成（RAG）

LLM 既有知识截止，又有有限的上下文窗口。RAG 的解决思路是：把你的文档嵌入（embed）到向量库中，在查询时取出语义最相关的片段并注入上下文——把模型的预测分布从"凭训练时记下的内容"扭转到"扎根、最新的事实"上。

步骤 01 —— 把所有内容嵌入

每篇文档都被 embedding 模型转换为一个稠密向量（约 1,536 维）。语义相似的文本在这个高维空间里彼此靠近——完全不需要关键词匹配。

步骤 02 —— 嵌入查询并搜索

用户问题以同样方式被嵌入。再用余弦相似度找出最近的文档向量——也就是与查询语义最相关的片段——通常取前 2–5 条。

步骤 03 —— 注入并生成

检索到的片段会被前置拼到 prompt 里，再交给 LLM。模型基于注入的事实生成，而不是依赖训练时记下的内容——在知识密集的任务上能大幅减少幻觉。
